Query big files without uploading them

Blinkql is a SQL workbench for engineers, analysts and supervisors with exports too big for a spreadsheet: machine logs, ERP and MES extracts, sensor data of a million rows or more. Open a CSV, Excel, Parquet or JSON file and query it in your browser. Nothing is uploaded.

From file to answer

  1. Open a file

    Drag a CSV, TSV, Excel, Parquet or JSON file onto the workbench, or add one from a web address. Each file becomes a table named after it, and the files from your computer are kept in your browser for your next visit.

    Open files

  2. Ask in SQL

    Write SQL with autocomplete for your tables and columns, and press Ctrl+Enter (⌘+Enter on a Mac) to run it. When a query goes wrong, the workbench says what happened, where, and how to fix it.

    Write queries

  3. See the answer

    Scroll through every row a query returns, even millions. Profile a table's columns without writing SQL, and chart a result as a bar, line, scatter, histogram or Pareto chart.

    Explore results

  4. Share what you found

    Export the results as CSV or Parquet, a chart as PNG, or the whole analysis as one HTML report. Or copy a link that holds the query and the chart's settings, but none of your data.

Your files stay on your computer

Blinkql has no server that receives your data. Your browser reads each file where it is, and the engine runs your queries inside the tab. You don't have to take that on trust. Each claim here says how to check it.

Privacy and storage has the details, and the source code is public.

Nothing is uploaded

Your files, queries and results aren't sent anywhere.

To check, open your browser's developer tools on the Network tab, import a file and run a query. No request carries your file or your results.

No account and no analytics

There's nothing to sign up for, no tracking cookies and no requests to other companies.

To check, watch the Network tab while you work. Every request goes to blinkql.karthik.nz, or to a web address you added a file from.

It works offline

After your first visit, the workbench opens without a connection, and files on your computer import and query as usual.

To check, turn off your connection and reload the workbench. The status bar says Offline, and your queries still run.

A share link holds no data

It holds the query and the chart's settings after the # in the address, a part browsers never send to a server.

To check, select Share. If the query has values written into it, such as a carrier's name, the dialog lists them before you copy the link.

What's kept stays in your browser

Copies of your files, your query history and your saved queries are kept for this site only, in this browser profile.

To check, open the Application tab of the developer tools in Chrome or Edge. Forget a table, or clear the site's data, to remove what's kept.

Specifications

Blinkql's specifications
File formats CSV, TSV, Excel (.xlsx), Parquet, JSON and JSON Lines
Where files come from Your computer, by dragging or choosing files. Or a web address starting with https://, if its server lets other sites read the file.
Comfortable file size Exports of 1–2 million rows. There's no fixed limit on size, only memory. The engine gets at most 4 GB in a browser tab, some computers allow less, and Parquet files go further than CSV.
Browsers The latest two versions of Chrome, Edge, Firefox and Safari on desktop. Phones and tablets open it, but its layout is made for a desktop screen.
SQL DuckDB's SQL, with autocomplete for your tables and columns
Data sent to a server None
Account None
Offline use Yes, once the workbench has loaded. Files from a web address need a connection.
Accessibility Targets WCAG 2.2 AA, checked automatically in light and dark themes. The core tasks work with a keyboard alone, and every chart can be read as a table.
Price Free

Built in the open

Blinkql is open source under the MIT licence. It was built in public across eight milestones, from the first query to version 1.0, and the roadmap shows what each one delivered. You don't need to write code to help, because the people with the files know best what the workbench should do.
