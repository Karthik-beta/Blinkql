Choose what to hand over

Every way out of the workbench uses the query you ran last, once it has finished without an error. While a query runs, or after one fails, the export buttons and Share are unavailable. Pick by what the other person needs and what they should see.

Export results as CSV or Parquet

The export buttons are at the right of the bar between the editor and the results, next to Share.

  1. Run a query, for example SELECT * FROM shipments WHERE delivered_date IS NULL on the sample shipments.
  2. Select CSV or Parquet.

The engine runs the query again and writes the whole result, however many rows it has, not only the rows on screen. While it works, the bar says "Exporting…". When it's done, the browser downloads the file and the bar says which, for example "Downloaded blinkql-result-2026-10-25-090503.csv". The name is the date and time of the export.

Choose CSV for a spreadsheet. Choose Parquet to open the result again in Blinkql or another data tool. Parquet keeps the column types and is smaller.

Export a chart as PNG

  1. Select Chart and set up the chart. Explore results explains the chart controls.
  2. Select Export PNG, at the right of the chart controls.

The image is the chart as it is on screen, in the page's current colours, at twice its size on screen so it stays sharp on slides. The file is named like blinkql-chart-2026-10-25-090503.png. Export PNG is unavailable while View as table is on.

Save an analysis as an HTML report

A report is a single HTML file to send to someone who doesn't use Blinkql. It opens in any browser, offline too, because it loads nothing from elsewhere.

  1. Run the query. To include a chart, select Chart and set it up, and leave View as table off.
  2. Select HTML report.

The report is titled "Blinkql report" and says when it was made and how many rows the result has. It shows the query, the chart if one was on screen, and the first 1,000 rows of the result. A longer result is labelled, for example "Result: first 1,000 of 2,500 rows". The chart is drawn in light and dark colours, and the report shows the one that matches the reader's setting. It prints in light colours. The file is named like blinkql-report-2026-10-25-090503.html.

A report holds data from your file. Check its rows before you send it.

Copy cells and queries

  • To copy cells, select them in the results table with Shift and the arrow keys, then press Ctrl+C (⌘+C on a Mac). They're copied as tab-separated text, one line per row, so a spreadsheet pastes them as the same block. If the selection includes the header row, the column names come too.
  • To copy a query you ran earlier, open History in the sidebar and select Copy SQL on its entry.

Share a query as a link

A share link holds the query and, if a chart is on screen, its settings. It holds no data. Whoever opens it runs the query on their own files, so it suits colleagues who have the same file or the same sample data.

  1. Run the query. If you want the link to open a chart, select Chart and set it up.
  2. Select Share. The Share query dialog shows the link.
  3. Select Copy link. The dialog says "Link copied". If the browser blocks the clipboard, the dialog selects the link so you can copy it yourself.

Values written into the query are part of the link, such as the carrier name in WHERE carrier = 'Deccan Haulage'. Before you share, the dialog lists them under "The query has values written into it, which anyone with the link can read": the first ten, and how many more there are. It doesn't look inside comments, and comments are part of the link too, so read the whole query before you share it. The link holds the query as it was last run, so to keep a value out of it, take the value out of the query and run the query again.

When someone opens the link, the workbench puts the query in their editor and says "Opened a shared query. Run it once its data is loaded." The query doesn't run by itself, because its tables may not be loaded yet. They load the same file, or the same sample from Load sample data, and select Run. The table names must match the ones in the query. A link that's been cut short or changed opens nothing, and the workbench says "That share link couldn't be read, so nothing was opened."
