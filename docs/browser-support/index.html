Supported browsers

Blinkql supports the latest two versions of Chrome, Edge, Firefox and Safari on desktop. Every change is tested automatically in Chromium, Firefox and WebKit, the browser engines behind all four. Phones and tablets can open the workbench, but its layout is made for a desktop screen.

Once the workbench has loaded, it opens without a network connection, and the status bar says Offline. Files on your computer still import and query offline. Files from a web address need a connection.

File size and memory

There's no fixed limit on file size. What limits you is memory. The engine runs inside the browser tab, which gives it at most 4 GB, and some browsers and computers allow less. How far that goes depends on the file's format and on the query.

When you import a file larger than half of that, the workbench warns you: "This file is large for this device's memory. If queries fail, add a LIMIT, select fewer columns or aggregate." The file still imports. The limit it compares with is 4 GB, or the computer's memory if the browser reports less than that. Chrome and Edge report it. Firefox and Safari don't, so there the warning starts at 2 GB.

To work with large files:

  • Use Parquet rather than CSV. The engine reads only the columns a query uses, and the file is smaller. To convert a CSV table, focus it in the Tables list and press C, or use its convert button. Open files explains converting.
  • Name the columns you need instead of SELECT *.
  • Filter and aggregate in SQL, so the result is small. Add a LIMIT when you only want to look at rows.
SELECT carrier, count(*) AS shipments, round(avg(freight_cost), 2) AS avg_cost
FROM shipments
WHERE ship_date >= DATE '2026-09-01'
GROUP BY carrier
ORDER BY avg_cost DESC

Files from a web address

To read a file from a web address, select Add from URL next to the Tables heading. The address has to meet a few conditions.

  • It starts with https://. Plain http:// works only for localhost and 127.0.0.1, so you can test with a server on your own computer.
  • Its path ends in a file name with one of the extensions Blinkql reads, such as orders.parquet. That name decides the format and the table's name.
  • The server allows other websites to read the file, through CORS. This is a setting on the server, not in your browser. Most cloud storage services have it off until the owner turns it on for https://blinkql.karthik.nz.
  • For Parquet, the server should support range requests, so the engine can download only the parts a query needs. Most cloud storage services do. Without them, the file still works, but the workbench warns "The server doesn't support range requests, so the whole file is downloaded every time it's read."

A file from a web address isn't kept in the browser. After a reload, add it again.

Storage space

Blinkql keeps a copy of each file you import from your computer, so its table comes back on your next visit. The copy is written straight to disk, so keeping a large file doesn't need memory for it. Each browser decides how much a site may store, usually as a share of free disk space, and the copies count towards it.

The copies are a convenience, not a backup. Browsers can delete a site's stored data when disk space runs low, and Safari can delete it after a period without visits. Blinkql asks the browser to keep the copies, but the browser decides. Keep your original files.

To save space, forget tables you no longer need, and convert CSV tables to Parquet, which replaces the kept copy with a smaller one. Privacy and storage lists everything the browser keeps and how to remove it.

Troubleshooting

An import that fails shows under the Tables list as "Couldn't import" with the file's name, followed by one of the messages below.

The file's format isn't recognised

"Not a CSV, TSV, Excel (.xlsx), Parquet, JSON or JSON Lines file" means the file's extension isn't one of .csv, .tsv, .xlsx, .parquet, .json, .jsonl or .ndjson. Blinkql judges the format by the extension alone. Rename the file if its extension is wrong. For a web address with no file name at the end, such as a download link ending in ?id=42, download the file and import it instead.

An Excel workbook won't open

  • "Excel 97–2003 workbooks (.xls) can't be read. Save it as .xlsx in Excel first." Open it in Excel and save it as an Excel workbook (.xlsx).
  • "The workbook can't be read. It may be password-protected or an older .xls file" means the file isn't a readable .xlsx. Remove its password, or save it as .xlsx in Excel, then import it again.

A web address won't load

  • "Enter a full address, starting with https://" or "Only https:// addresses can be read." Check the address you typed.
  • "The server doesn't let other websites read this file (it doesn't allow CORS). Download the file and import it instead." The browser couldn't read the file. The usual reason is CORS, but you see the same message when you're offline or the server can't be reached, because the browser doesn't say why a request failed. Ask the file's owner to allow https://blinkql.karthik.nz, or download the file and import it.
  • "The server answered" followed by a status, such as 403 Forbidden or 404 Not Found. The server refused the request or has no file there. Check the address, and for a private file, that the link gives access without signing in.

A query runs out of memory

The error panel says "The query ran out of memory". Filter or aggregate in SQL, or add a LIMIT, so less data has to fit in the browser. Converting a CSV table to Parquet also helps. Write queries covers the other error messages.

The engine stopped or didn't start

If the engine itself fails, the error panel says "The engine stopped" and the status bar starts with "Engine stopped". Select Restart engine. Your tables are imported again automatically. The query may have been fine, so run it again, or narrow it first if it read a lot of data.

If the status bar says "Engine failed to start", select Restart engine to try again. If it keeps failing, update your browser to a supported version.

Tables are gone after a reload

If the Tables list said "This browser can't keep these files, so their tables will be gone after a reload.", the browser had no room for the copy or doesn't allow sites to store files. This can happen in private windows, when storage is full, and when site data is blocked in the browser's settings. Use a normal window, free some space, or allow site data for blinkql.karthik.nz. Tables from a web address are never kept, so add those again.
