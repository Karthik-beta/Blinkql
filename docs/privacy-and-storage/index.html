Your files stay on your computer

Blinkql has no server that receives your data and no accounts. When you open a file, your browser reads it and the engine runs your queries inside the tab. Your files, queries and results aren't sent anywhere, and Blinkql collects nothing about them.

Data leaves the workbench only when you take it out yourself.

  • An export, a chart image or an HTML report is a file in your downloads folder. It holds the data it shows, so check it before you send it.
  • Copied cells go to your clipboard.
  • A share link holds the query and the chart's settings, never the results. Values written into the query, such as 'Deccan Haulage' in WHERE carrier = 'Deccan Haulage', are part of the link, and the Share query dialog lists them before you copy it.

Share and export explains each of these.

What the browser keeps between visits

So that your work is still there when you come back, Blinkql keeps a few things in your browser. They're stored for this site only, in this browser profile. Another site can't read them, and neither can Blinkql in another browser or on another computer.

Some things aren't kept. A file you add from a web address isn't copied, so after a reload you add it again. The text in the editor and the results on screen are gone when you close the tab. To keep a query, open Saved in the sidebar, give it a name and select Save.

The first time Blinkql keeps a file, it asks the browser not to delete stored files when disk space runs low. The browser can say no, and some browsers ask you first. In a private window, or if storage is full or blocked, the workbench says "This browser can't keep these files, so their tables will be gone after a reload." The tables still work until then. Browser support and limits covers storage limits.

What goes over the network

The workbench makes only these requests:

  • Loading the workbench downloads its page, scripts, styles, fonts and engine from blinkql.karthik.nz, including the engine's readers for Parquet, JSON and Excel. That's code coming in. Nothing goes out. After the first visit they come from the browser's copy.
  • When you add a file from a web address, your browser asks that server for the file directly. It first asks for one byte, to check the server allows it, then for the parts your queries need. Blinkql's own site isn't involved.
  • From time to time the browser checks for a new version of the workbench. When there is one, the status bar says "A new version of Blinkql is ready." with Reload and Not now.

There are no analytics, no cookies for tracking and no requests to other companies' servers. A share link keeps the query after the # in the address, and browsers don't send that part to any server.

Remove what Blinkql keeps

  • To remove one table and its kept copy, select its forget button in the Tables list. The button's tooltip starts with "Forget". From the keyboard, focus the table and press Delete. There's no confirmation.
  • To remove a saved query, open Saved in the sidebar and select Delete on it.
  • To remove everything, including the query history, clear the site data for blinkql.karthik.nz in your browser's settings. In Chrome and Edge, you can also open the developer tools and select Application, then Storage, then Clear site data.

Clearing site data doesn't touch the original files on your computer. Blinkql only ever reads those.

Check it yourself

You don't have to take this page's word for it. Your browser's developer tools show what the workbench does.

  1. Open the developer tools and select the Network tab.
  2. Import a file and run a query on it.
  3. Look at the requests. None of them carry your file or your results, and none go to a server you didn't ask for.

To see what's stored, open the Application tab in Chrome or Edge, or Storage in Firefox. The query history and saved queries are in IndexedDB, in a database called blinkql. The tour's flag is in local storage, under blinkql-tour-seen.

Blinkql's source code is public on GitHub, if you'd rather read how it works.
