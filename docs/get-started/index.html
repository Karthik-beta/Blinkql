Open the workbench

Go to the workbench. There's nothing to install and no account to create. The engine that runs your queries starts in the background, and the status bar at the bottom of the window says Starting engine… until it's ready, then Engine ready.

The workbench has four parts:

  • The sidebar on the left lists your tables under Tables, with the buttons that add them. Below it, History and Saved hold your queries.
  • The SQL editor fills the top of the main area, with Run above it.
  • The results sit below the editor. Table and Chart switch between the grid and a chart of the same result.
  • The header has Commands, which opens the command palette, and Templates, which opens the ready-made analyses.

Take the tour

Until you've run a query or taken the tour, the empty results area offers a three-step tour. Click Take the tour. A small panel opens in the corner, and each step has a button that does the step for you:

  1. Load quality checks loads the sample table quality_checks and puts a query for each machine's reject rate in the editor.
  2. Run the query runs it. The results show one row per machine.
  3. Show as a chart draws the result as a bar chart of reject rate by machine. Done closes the tour.

You can do any step yourself instead, with the workbench's own buttons. To leave the tour early, click Skip tour or End tour, or press Esc. To take it again later, open the command palette with Ctrl+K (⌘+K on a Mac) and choose Take the tour.

Load sample data

Blinkql comes with sample data from a made-up factory: a week of production and a quarter of its shipments. The browser generates it, so nothing is downloaded. To load a sample, click Load sample data under the tables and pick one. Each sample becomes a table.

Run your first query

With quality_checks loaded, write a query in the editor. Clicking a table's name under Tables types it into the editor at the cursor.

SELECT machine_id, sum(rejected) AS rejected, sum(inspected) AS inspected
FROM quality_checks
GROUP BY machine_id
ORDER BY rejected DESC

Press Ctrl+Enter (⌘+Enter on a Mac), or click Run. The bar under the editor shows how many rows came back and how long the query took, for example 8 rows in 40 ms, and the rows appear in the grid below it. If something's wrong with the query, a panel under the editor says what and where. Write queries covers autocomplete, running part of a query and fixing errors.

Open your own file

Drag a CSV, TSV, Excel (.xlsx), Parquet or JSON file from your computer anywhere onto the workbench, or click Import files, the upload icon next to the Tables heading. The file becomes a table named after it, so Line 3 output.csv becomes line_3_output. The browser reads the file where it is, and nothing is uploaded. Open files covers every format, files on the web, and how Blinkql keeps your files between visits.

Come back later

When you open the workbench again in the same browser, the tables you opened from your computer or loaded as samples, your query history and your saved queries are still there. Tables you opened from a web address aren't kept, so open the address again. Once the workbench has loaded, it also works offline, and the status bar shows Offline while you have no connection. When a new version of Blinkql is available, the status bar says A new version of Blinkql is ready. Click Reload to start using it.

From here, Explore results shows how to work with the grid and charts, and Analysis templates runs ready-made analyses such as OEE on the sample data or your own files.
