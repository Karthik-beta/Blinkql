Write SQL in the editor

Blinkql's engine is DuckDB, so you write DuckDB's SQL. DuckDB's documentation describes its statements and functions. Query a table by the name it has under Tables. To type a table's or a column's name into the editor at the cursor, click it, or select it and press Enter. Names that need quotes in SQL get them.

SELECT carrier,
  count(*) AS shipments,
  round(100 * avg(CASE WHEN delivered_date <= promised_date THEN 1 ELSE 0 END), 1) AS on_time_pct
FROM shipments
WHERE delivered_date IS NOT NULL
GROUP BY carrier
ORDER BY on_time_pct DESC

This query runs on the Shipments sample. Get started shows how to load it.

Use autocomplete

As you type, the editor suggests SQL keywords, types and functions, and the tables and columns you've opened. A function's suggestion shows its arguments, and a column's shows its type. Columns are also suggested after a table's alias, as in s. for FROM shipments s.

  • To ask for suggestions at the cursor, press Ctrl+Space.
  • To pick a suggestion, move to it with ↑ and ↓ and press Enter.
  • To close the suggestions, press Esc.

Tab doesn't indent or pick a suggestion. It moves the focus out of the editor, as it does everywhere else on the page. Keyboard shortcuts lists the editor's other keys.

Run all or part of a query

To run the query, press Ctrl+Enter (⌘+Enter on a Mac) or click Run. To run only part of what's in the editor, select that part first. This is how you keep several queries in the editor and run one at a time.

While a query runs, the button shows Running and the time so far. The first rows appear in the results as soon as the engine has them, and the rest follow. When the query ends, the bar under the editor shows how many rows it returned and how long it took, such as 8 rows in 40 ms. A new result replaces the previous one.

Cancel a running query

To cancel a running query, press Esc anywhere on the page, or click Cancel, which appears next to Run while a query runs. You can also choose Cancel query in the command palette. The bar under the editor then says Cancelled after and the time, and Blinkql clears the results, even if some rows had arrived.

Running another query cancels the one that's running. A single statement that only reads, such as a SELECT, stops in the engine straight away. A query of several statements, or one that changes data such as INSERT, can't be stopped once it's sent. The engine finishes it, and Blinkql doesn't show its result.

Fix an error

When a query fails, a panel under the editor says what went wrong in plain words and suggests a fix. It shows the line with the error and a caret under the spot, and the editor underlines that spot. Click Go to error to move the cursor there. To see the engine's own wording, open DuckDB's message. The underline goes away when you next edit the query.

Find and keep your queries

Blinkql records every query you run under History in the sidebar, newest first, with when it ran and how it went. History keeps your last 500 runs, including the ones that failed or were cancelled.

  • To find a past query, type part of its SQL in Search history.
  • To put a past query back in the editor and run it, click its Run again button.
  • To copy its SQL, click Copy SQL.

To keep a query you come back to, switch to Saved, type a name in Name and click Save. Blinkql saves everything in the editor under that name. Each saved query has buttons to open it in the editor, run it, rename it and delete it. History and saved queries stay in your browser between visits.

Tables you create in SQL, with CREATE TABLE for example, last until you reload the page, and they aren't listed under Tables. To keep a result, export it as a file and import that file. Share and export shows how.
