Scroll through the results

The results grid shows everything a query returns, whether that's 8 rows or millions. Rows appear as soon as the engine has them, so you can start scrolling before a long query ends. The grid draws only the rows in view, so scrolling through millions of rows costs about the same as scrolling through eight.

  • Numbers line up on the right, and everything else on the left.
  • An empty value shows as NULL in grey.
  • Each column starts as wide as its name and the values in its first 100 rows, up to 50 characters. To see a value that's cut short, hover over it.

To resize a column, drag the right edge of its header. Double-click the edge to fit the column to the values in view.

Look at a table without writing SQL

Each table under Tables has buttons that run a query for you and show its result in the grid. Select a table and press the key, or click the button next to its name.

  • Show rows (R) shows every row of the table. You can then chart them.
  • Profile (P) shows one row per column with its type, minimum and maximum, approximate number of distinct values, average, standard deviation, quartiles, row count and percentage of nulls. The result's columns are column_name, column_type, min, max, approx_unique, avg, std, q25, q50, q75, count and null_percentage.

For a quicker look, show the table's columns with the arrow next to its name. Each column lists its type, the percentage of nulls and the number of distinct values, for example 0% null · 8 distinct. A count with ~ in front is an estimate. Blinkql counts exactly when a column has up to about 1,000 distinct values.

Chart a result

To chart the last result, click Chart above the results. Table takes you back to the grid, which keeps its scroll position and selection. A chart is drawn from the whole result, not only the rows in view. Choose what to draw with the settings above the chart:

  • Chart type picks Bar, Line, Scatter, Histogram or Pareto.
  • X picks the column along the bottom.
  • Aggregate picks count, sum, avg, min or max, worked out for each bar or step. Bar, line and Pareto charts have it.
  • Y picks the column to aggregate or plot. It appears for scatter charts, and when the aggregate isn't count.
Chart typeX can beWhat it draws
BarAny columnOne bar per value of X, largest first, up to 50 bars.
LineA number, date or timestampThe aggregate at up to 1,000 evenly spaced steps along X.
ScatterA number, date or timestampOne point per row, for up to 5,000 rows picked at random. The same rows are picked each time.
HistogramA numberHow many rows fall in each of 30 equal ranges of X.
ParetoAny columnBars from largest to smallest, for the 50 largest, with a line for the running percentage of the total. The aggregate is count or sum.

For example, to see which reasons cause most downtime, run this on the Breakdown log sample, then choose Pareto, X reason, Aggregate sum and Y downtime_min:

SELECT reason, date_diff('minute', started_at, ended_at) AS downtime_min
FROM breakdowns

Read a chart as a table

Click View as table to see the chart's points as a table, with the same columns the chart uses. Click it again to go back to the chart. Screen readers announce what each chart shows and a summary of its data, such as how many bars it has and which is highest.

To save the chart as an image, click Export PNG. Share and export covers saving results as files, a report or a link.
